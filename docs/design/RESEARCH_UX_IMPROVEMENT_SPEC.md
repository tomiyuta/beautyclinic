# リサーチ機能 UI/UX改善要件定義書

## 1. 概要
本ドキュメントは、「市場調査 (`/market-research`)」および「SNS調査 (`/sns-research`)」機能のUI/UXを刷新するための要件定義である。
現状のテキストベースの入力フォームとリスト表示形式から、直感的で視覚的なインターフェースへと移行し、ユーザーの意思決定速度と作業効率を向上させることを目的とする。

## 2. 現状の課題 (As-Is)
*   **入力の単調さ**: テキストフィールドとプルダウンのみで構成されており、直感的な選択が難しい。
*   **履歴の検索性**: 過去の調査結果が単純な時系列リストであり、再利用や比較が困難。
*   **結果の視認性**: テキストデータが羅列されるのみで、重要なインサイトが一目で把握できない。
*   **待機時間のストレス**: AI処理中のフィードバックが乏しく、体感待ち時間が長い。

## 3. 改善要件 (To-Be) - MECE分析に基づく分類

### A. Input (入力・設定フェーズ)
ユーザーの認知負荷を下げ、スムーズな調査開始を支援する。

1.  **ビジュアルセレクターの導入**
    *   **SNS調査**: プルダウンではなく、各プラットフォーム（X, Instagram, YouTube, TikTok）のアイコンを用いた大きなカード型選択UIを採用する。
    *   **市場調査**: 「トレンド」「価格」「競合」の各モードをタブまたはカードで視覚的に切り替え可能にする。

2.  **インテリジェント入力補助**
    *   **キーワード提案**: 過去の入力履歴や、選択したカテゴリに基づく人気キーワードをチップ形式で提案する。
    *   **テンプレート機能**: 「美容クリニック競合調査セット」など、よく使う条件（エリア・キーワード・対象）をプリセットとして保存・呼び出し可能にする。

3.  **条件の可視化**
    *   選択中の条件（エリア、キーワード、除外ワード）をタグ形式でリアルタイムに表示し、ワンクリックで削除可能にする。

### B. Process (実行・待機フェーズ)
処理待ち時間を「無駄な時間」から「期待感を高める時間」へ転換する。

1.  **リッチなローディング表現**
    *   単なるスピナーではなく、進捗ステップ（例:「APIに接続中...」→「データを収集中...」→「分析中...」）を表示するステッパーUI。
    *   待機中に「調査のヒント」や「AI活用の豆知識」をランダム表示するスケルトンスクリーン。

### C. Output (結果・履歴フェーズ)
データを「読む」のではなく「見る」だけで理解できるようにする。

1.  **履歴のダッシュボード化**
    *   単純なリストではなく、カードグリッドレイアウトを採用。
    *   各カードには「キーワード」「日時」に加え、**AIが生成した要約（ワンラインサマリー）**を表示。
    *   結果のポジティブ/ネガティブ判定を色枠（緑/赤）やアイコンで表現。

2.  **高度なフィルタリングと検索**
    *   **フリーワード検索**: 過去の調査内容をキーワード検索可能にする。
    *   **ファセット検索**: プラットフォーム別、期間別、AIモデル別での絞り込み機能。
    *   **お気に入り機能**: 重要な調査結果をピン留めし、上部に固定表示する。

3.  **再実行アクション**
    *   履歴カードに「この条件で再調査」ボタンを配置し、ワンクリックで最新データを取得可能にする。

### D. Structure (構造・共通基盤)
一貫性のあるユーザー体験を提供する。

1.  **共通レイアウトコンポーネント**
    *   市場調査とSNS調査で共通の `ResearchPageLayout` コンポーネントを定義し、ヘッダー・履歴・入力の配置を統一する。
    
2.  **ドロワー/モーダル詳細表示**
    *   履歴をクリックした際、ページ遷移せず右側からドロワー（サイドパネル）で詳細を表示し、一覧を見ながら詳細を確認可能にする。

## 4. 実装詳細要件

### 4.1. 画面構成案
*   **ヘッダーエリア**: タイトル、使用AIモデル表示、クレジット残高（将来用）
*   **メインエリア (左側/上部)**:
    *   調査タイプ選択（カードUI）
    *   詳細条件入力フォーム（動的切り替え）
    *   アクションボタン（大型・高コントラスト）
*   **履歴エリア (右側/下部)**:
    *   ツールバー（検索・フィルタ・ソート）
    *   結果カードグリッド（Masonryレイアウト推奨）
    *   結果詳細ドロワー（`Sheet` / `Drawer` コンポーネント）

### 4.2. 推奨コンポーネント設計 (React/Next.js)

```typescript
// 1. ビジュアルな選択カード
interface SelectionCardProps {
  icon: ReactNode;
  title: string;
  description: string;
  isSelected: boolean;
  onClick: () => void;
}

// 2. 履歴カード
interface HistoryCardProps {
  type: "market" | "sns";
  platform?: string; // SNSの場合
  query: string; // キーワードやエリア
  summary: string; // AIによる要約
  timestamp: Date;
  status: "success" | "error";
  onRerun: () => void;
  onViewDetail: () => void;
}

// 3. フィルタバー
interface FilterBarProps {
  onSearch: (text: string) => void;
  onFilterChange: (filters: FilterState) => void;
}
```

## 5. 技術的制約・留意事項
*   既存の `tRPC` クエリ (`api.marketResearch.list`, `api.snsResearch.list`) を活用すること。
*   現状のデータ構造 (`processedData` が文字列/JSON混在) を考慮し、表示時にパースして整形するロジック (`formatTrendDataForDisplay` 等) は共通ユーティリティとして切り出すこと。
*   アコーディオン (`details/summary`) は廃止し、ドロワーまたはモーダルでの詳細表示に移行すること。

## 6. 完了条件 (Definition of Done)
1.  **SNS調査**: プラットフォーム選択がアイコン付きカードで選択できること。
2.  **市場調査**: 3つの調査タイプがタブまたはカードで直感的に切り替えられること。
3.  **履歴機能**: 過去の調査結果がカード形式で表示され、キーワード検索・フィルタリングができること。
4.  **詳細表示**: 履歴をクリックすると、ページ遷移なしで詳細情報が表示されること。
