# 戦略分析における市場調査データ任意選択機能 要件定義書（マルチ版）

## 1. 背景・目的
現在、戦略分析機能では、システムが自動的に「最新の市場調査データ」を各カテゴリ1件ずつ取得して使用している。
しかし、市場調査機能がマルチAI（Gemini, ChatGPT, Grok, Claude）化されたことにより、「Grokの速報性」と「ChatGPTの分析力」の両方を組み合わせたいなど、**複数のデータソースを統合して分析したい**というニーズがある。
これに対応するため、戦略分析に入力するソースデータをユーザーが任意に、かつ**複数選択**できる機能を実装する。

## 2. UI/UX デザイン方針

### 2.1 コンセプト
**「Multi-Source Synthesis（多角的ソース統合）」**
複数の異なるAIや異なる日時の調査結果を選択可能にし、戦略AI（Claude Opus等）にそれらを統合・解釈させることで、より堅牢な戦略立案を実現する。

### 2.2 画面構成案

#### A. 戦略分析設定エリア（既存改修）
- 「市場調査データを含める」トグルの下に、**「使用するデータを選択」**ボタンを配置。
- 選択状態の概要表示を「件数」ベースに変更。
    - 例: `トレンド分析: 2件選択中 (Grok, ChatGPT)`
    - 例: `価格調査: 1件選択中 (Claude)`

#### B. データ選択ドロワー（新規作成）
- **タブ切り替え**: 「トレンド分析」「価格調査」「競合分析」の3タブ。
- **リスト表示**: 各カテゴリの過去データをカード形式で表示。
- **選択操作**: **チェックボックス**による複数選択。
- **バリデーション表示**:
    - 各カテゴリにつき**最大3件まで**選択可能（トークン制限のため）。
    - 4件目を選択しようとすると、「これ以上選択できません」とトーストまたはアラートを表示。
- **一括操作**: 「最新3件を選択」などの便利ボタン。

### 2.3 カード情報の詳細
各データカードには以下を表示し、比較検討しやすくする。
- **AIプロバイダー**: アイコンと名前（Gemini/ChatGPT/Claude/Grok）。
- **実施日時**: `2024/11/28 14:30`。
- **場所**: `表参道`。
- **文字数/トークン**: `約2,000文字`（選択時の目安として）。

## 3. 機能要件

### 3.1 フロントエンド
- **State管理**: 配列でIDを管理。
    - `selectedTrendIds: number[]`
    - `selectedPriceIds: number[]`
    - `selectedCompetitorIds: number[]`
- **選択制限ロジック**:
    - `selectedTrendIds.length >= 3` の場合、未選択項目の選択を無効化（disable）。

### 3.2 バックエンド (TRPC)
- **戦略分析API (`analyzeMarketPosition`) 変更**:
    - 入力スキーマ (`input`) を配列対応に変更:
        ```typescript
        marketDataSelection: z.object({
          trendIds: z.array(z.number()).optional(),
          priceIds: z.array(z.number()).optional(),
          competitorIds: z.array(z.number()).optional(),
        }).optional()
        ```
    - ロジック変更:
        - `trendIds` が指定されている場合: `where: { id: { in: input.marketDataSelection.trendIds } }` で一括取得。
        - 取得した複数のデータを結合またはリスト化してプロンプトに渡す。
            - 結合形式:
              ```json
              [
                { "source": "Grok", "date": "...", "data": { ... } },
                { "source": "ChatGPT", "date": "...", "data": { ... } }
              ]
              ```
        - `trendIds` が未指定の場合: 従来通り最新1件を取得。

## 4. トークン管理の重要性
複数選択により、プロンプトサイズが肥大化するリスクがある。
- **対策1**: 前工程で実装した「JSON形式統一 & 5000文字制限」を厳格に適用。
- **対策2**: フロントエンドでの選択数制限（最大3件）。
- **対策3**: バックエンドで合計文字数をチェックし、上限を超える場合は古いデータから順に「要約」プロパティのみを使用するなどのフォールバック処理を検討（今回はまずは制限のみで対応）。

## 5. 今後の拡張
- **比較モード**: 複数の調査結果の「差異」に焦点を当てて分析するモードの追加。
